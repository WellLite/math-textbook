# 数学是怎样想出来的？

## 我为什么想写这本书

学矩阵乘法的时候，我学会了拿左边的一行去乘右边的一列。给我两张数字表，我就能算出第三张。可要是把公式擦掉，只留下那两张表，我凭什么会想到这样乘？为什么连乘的顺序都要紧？学向量叉乘时我也有相似的疑问。等我已经记熟了怎么算，那个更早的问题还在：当初究竟遇到了什么困难，值得为它发明这么一个运算？

我常想象一个人，坐在一间空屋子里。他足够聪明，却没有读过现代数学的教材。如果他也能走到矩阵乘法，他的第一步会是什么？

我们的样章给他出了一个小问题。画面上有一个箭头，先把整幅图拉高，再向右推斜。能不能只算一次，就知道箭头最后指向哪里？他可以先盯住向右一步和向上一步的两个箭头，记录它们各自去了哪里。可他很快会遇到一个麻烦：如果中间的点能随意乱跑，知道这两个箭头的去向又有什么用？追问到这里，才有理由去找一类能保留位移相加和缩放的变换。等他把两个变换接起来，亲手算出最终的水平位移，公式里那两个乘积为什么要相加，就有了来历。[从图形变换到矩阵乘法](chapters/matrix-multiplication.md)

我想邀请大家一起做的，就是把数学里这样的路写出来。有时一位老师花了很多年，才找到能让学生自己想到下一步的那个问题。如果这些讲法能彼此接起来，一个没有机会坐进那间教室的孩子，也可以从同一个问题出发，走到足够远的地方。

## 我们想写到哪里

我们想写一套可以用很多年、也可以直接拿进课堂的教材。起点可以低到“怎样说清楚每一个”和“数完一个以后怎样得到下一个”，也可以从点、线和形状开始。希望这些路能一路通向中学数学、数学奥林匹克、大学公共数学和数学专业的主要课程。读者若在某一步卡住，应当能沿着书里的联系，找到眼下真正缺的那块知识。

一条路也可以与另一条路汇合。学习矩阵时，从几何变换进来，会关心箭头去了哪里；从方程组进来，会关心几个未知数怎样一起变化。两条路相遇的地方，值得专门用一段话告诉读者，他们已经在研究同一个对象。

我们尤其在意这几件事：

- **把发现的机会留给读者。** 引入新工具前，先给出一个用手头知识值得尝试的问题。如果一个很自然的尝试会失败，就让读者看到它走到了哪里，究竟卡在哪一步。
- **让直观经得起追问。** 图像可以带人猜到结论，正文还要说清用到了哪些条件、每一步为什么成立。适合整理成规范书面证明的部分，可以另附。反例、例题、证明和图解在需要时出现，每章都可以有自己的结构。
- **把前置知识指到具体的一步。** 讲“四点共圆”时，可以指出哪一步用圆周角定理，哪一步借助定角轨迹反推第四个点的位置。另一种观察角度也欢迎写进来，并说清它帮人看见了什么。[四点共圆](chapters/concyclic.md)

## 一起写

你可以是熟悉某个领域的数学研究者、记得学生在哪里卡住的老师，也可以是刚读到一半、能准确说出“我从这句话开始跟不上了”的学生。这样的反馈足以开启一次有价值的修改。

- **提问或纠错**：在 [Issues](https://github.com/WellLite/math-textbook/issues) 贴出具体段落，告诉我们你手头已有的知识，以及你在哪一步失去了线索。
- **修改一小段**：打开对应的 Markdown 文件，点铅笔编辑，提交 Pull Request（PR，合并请求）。维护者和其他读者可以逐句讨论。
- **写一整章**：可以先开 Issue 说说打算从哪个问题起步，方便其他作者接应。也可以直接 fork 仓库，在自己的分支写作，然后提交 PR。欢迎在草稿阶段就发出来，一起找断点、试反例。

**署名按实际贡献记录。** 建议、校对和局部修订会在 Issue、PR 或提交历史中留下记录，通常无需把贡献者列为整章作者。独立撰写一章的作者会在该章标题下显著署名，多人共同完成则列出共同作者。原创图解、独立证明或关键段落，即使很短，也可以在对应位置单独署名。请告诉我们你希望使用的姓名、笔名或 GitHub 账号。章节署名说明谁做了哪些工作，版权依适用法律及具体原创表达确定。[贡献指南](CONTRIBUTING.md) · [授权与再利用](RIGHTS.md)

## 本地阅读与预览

可以直接在 GitHub 阅读章节。若想在本机查看互动地图和公式排版，准备 Python 3、Pandoc，在仓库根目录运行：

```sh
python3 tools/build.py
python3 -m http.server 8000 --directory _site
```

然后用浏览器打开 `http://localhost:8000/`。贡献者提交的是 `chapters/` 的正文和 `content/map.json` 的知识关系；学生网站从这些源文件生成。
